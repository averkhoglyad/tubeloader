# Слои презентации раздельны, ручной флоу без decompose

Tubeloader получит два фронтенда: Compose Desktop (M1) и mosaic TUI (M2, эксперимент).
Решено: общий шов между ними — только ядро (фасад команд + Flow/StateFlow событий) и доменные
типы. Слой презентации (UI-состояние, роутинг экранов) отделён от рендеринга и у каждого
фронтенда свой; UI-компоненты между фронтендами не переиспользуются, даже при общем
Compose-runtime у Desktop и mosaic. Флоу состояний — ручной (StateFlow + sealed-иерархия
экранов), без компонентного фреймворка.

## Considered Options

- **Ручной флоу** (принято): минимум машинерии при 2–3 экранах M1; state-слой — plain Kotlin +
  StateFlow, mosaic собирает его нативно через общий compose-runtime, мост не нужен.
- **Decompose** (отклонён, отложен): отдаёт чистое state/UI-разделение и роутинг, но требует
  собственного моста к mosaic (официальных расширений нет: Compose, Android Views, SwiftUI,
  React) и тянет lifecycle-машинерию, избыточную для масштаба M1.

## Consequences

- Требование «слой презентации отделён от рендеринга» — архитектурный инвариант (`AGENTS.md`),
  ручной флоу — его реализация, а не компромисс.
- Переход на decompose возможен позже как рефакторинг фронтенда, ядро не затрагивается.
- Критерии пересмотра: экранов больше ~5, back-stack/retained state подтверждённая работа
  extensions-compose с mosaic.
