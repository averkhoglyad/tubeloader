# Архив `.gitverse` (снят 02.10.2026)

Снимок директории `.gitverse` на коммите `6f5e845`. GitVerse переведён на GitHub-флоу, рабочая
копия директории удалена; здесь она сохраняется целиком, потому что `pr_rules` — вход
внешнего потребителя (GigaCode-ревьюера), которого ни один сборщик не проверяет.

## Состав

- `pr_rules/protocol.md`, `pr_rules/checklist.md` — правила агента-ревьюера GitVerse: роль
  (read-only, approve / changes requested), оси STANDARDS и SPEC, требование `path:line` +
  доказательство на каждую находку; карта канонических мест. Локацию задавал пользователь.
- `scripts/tracker-notify.sh`, `scripts/tracker.env` — тонкий адаптер GitVerse-раннера и его
  провайдерский конфиг. Адаптер знал только событие и путь к конфигу, домена не касался.
- `workflows/tracker-push.yml` — уведомление в Weeek о коммитах пуша.
- `workflows/tracker-pr.yml` — уведомление о слиянии PR.

Действующая замена — `.github/scripts/` и `.github/workflows/`.

## Достоверность

Файлы лежат байт-в-байт как в коммите `6f5e845` (сверено `git hash-object <archived>` против
`git rev-parse HEAD~:<path>` перед коммитом удаления, 6/6 идентичны). История git их не теряет —
восстановление рабочей копии: `git checkout 6f5e845 -- .gitverse`.

## Причина снятия

Не GitVerse как хостинг, а именно этот слой: у него не было живых потребителей в репозитории.
Защита ветки там выключена (`protected: false`), Actions — тоже (`has_actions: false`), поэтому
воркфлоу не исполнялись, а `pr_rules` читает только внешний ревьюер. Сохранены потому, что
решение обратимо: возврат GitVerse-ревью не должен начинаться с восстановления правил из истории.
